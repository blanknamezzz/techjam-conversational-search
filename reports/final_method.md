# Track 4 离线混合检索 Agent

## 方案概览

最终 V6 Agent 采用离线优先架构：

```text
多轮消息 → 状态更新／Intent Override → 主动澄清
        → Porter BM25 Top 160 + MiniLM Dense Top 160
        → 加权 RRF → 三值约束重排序 → 显式硬约束门控 → Top 10
```

- BM25 负责品牌、品类、商品词和精确属性。
- 本地 `all-MiniLM-L6-v2` 负责用途和语义补召回。
- Dense 的 RRF 权重为 0.25，BM25 为 1.0，避免语义噪声主导结果。
- 完整约束短语作为独立证据，最终权重为 0.70。
- 约束采用 `MATCH / VIOLATION / UNKNOWN`，缺失值不会被误当成违反。
- 只有用户显式硬要求且商品存在明确反证时才执行最终门控。
- 每轮可以同时返回推荐和一个结构化澄清字段。
- Dense 索引或模型不可用时自动退回 BM25，不依赖网络或 API。

## 本地模型与成本

- 模型：`sentence-transformers/all-MiniLM-L6-v2`。
- 商品数：50,000。
- 向量维度：384。
- `float32` 向量矩阵约 73 MiB。
- 本机首次构建耗时约 118 秒；后续直接加载缓存。
- 运行不产生 API Token，`usage` 均为 0。

## 已知局限

- 公开模拟器的条件主要来自商品元数据，私有自然语言改写可能更复杂。
- 验证集 Boundary 只有 2 条且均未命中，样本太少，不能据此稳定估计边界场景效果。
- 当前 Intent Router 和槽位提取以确定性规则为主，复杂否定和关系表达仍可能出错。
- Dense 模型和索引未提交到 Git；缺失时虽然可以运行，但会退回 V1 级别能力。
- 约束重排序是可解释规则，不是经过大规模标注训练的 Learning-to-Rank 模型。
- 可选在线 API 示例默认完全关闭；最终方案不依赖网络。
- V7 的无密钥实验与 V6 完全一致，证明凭据缺失时降级路径不会改变结果；实际在线收益仍需使用新的有效凭据做 A/B。

## 安全与复现

- API Key 只允许来自环境变量，仓库不得包含任何密钥。
- `artifacts/`、`.env`、目录数据和运行结果均按用途进行 Git 忽略。
- 官方 `evaluator/local_evaluator.py`、公开标签和评分公式保持不变。
- 原始官方 BM25 已保存在 `starter/baseline_agent.py`，用于公平消融。
